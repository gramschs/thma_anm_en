5.2 Swivel Arm at a Conveyor Belt

In Chapter 5.1 we used the rotation matrix to compute where the arm of a SCARA robot ends up after a rotation. In this chapter we apply it to a packaging line in which a swivel arm with only one joint does the work. Work through the parts in pairs if possible, and in order, since each part builds on the previous one.

Project: Swivel arm at a conveyor belt (✩✩)

On a packaging line, housing lids arrive on a conveyor belt. A swivel arm picks up each lid from the belt and places it in a box. The arm has a single rotary joint at the origin and is L=0.6 mL = 0.6\,\text{m}L=0.6m long from the joint to the gripper. In the home position α=0\alpha = 0α=0, it points along the xxx-axis, and the gripper is over the lid on the belt. The arm can swivel counterclockwise from 0°0°0° to 180°180°180°.

# Given plotting function: just run it, you do not need to understand it.
def plot_robot(arms, parts=None, targets=None, path=None, surroundings=None,
               labels=None, title='', limit=0.8):
    """Plots a robot arm in top view.

    arms: points of an arm as an array, row = [x, y], from the first joint to
          the gripper, or a list of such arrays for several positions
    parts: corner points of the part in the gripper as an array, or a list
           with one array per position (optional)
    targets: target points as an array, row = [x, y], marked as crosses (optional)
    path: gripper positions as an array, row = [x, y], drawn as a dashed
          line with dots (optional)
    surroundings: corner points of areas such as a conveyor belt or a box as
                  an array or a list of arrays, filled in gray (optional)
    labels: legend entries, one per position (optional)
    title: plot title
    limit: visible range from -limit to +limit in m
    """
    blue, red, orange, gray = '#005A94', '#E60000', '#E87846', '#484949'
    colors = [blue, red, orange, gray]
    if isinstance(arms, np.ndarray):
        arms = [arms]
    if isinstance(parts, np.ndarray):
        parts = [parts]
    if isinstance(surroundings, np.ndarray):
        surroundings = [surroundings]
    fig, ax = plt.subplots(figsize=(6, 6))

    # surroundings: areas such as a conveyor belt or a box
    if surroundings is not None:
        for area in surroundings:
            ax.fill(area[:, 0], area[:, 1], facecolor='#DDDEDE',
                    edgecolor=gray, linewidth=1, zorder=0)

    # base at the origin
    ax.add_patch(plt.Circle((0, 0), 0.06, facecolor='#CCDEE9', edgecolor=blue,
                            linewidth=1.5, zorder=1))

    # gripper path as a dashed line with dots
    if path is not None:
        ax.plot(path[:, 0], path[:, 1], color=gray, linestyle='--', linewidth=1,
                marker='o', markersize=3, label='Gripper path', zorder=1)

    # arms: joints as circles, gripper as a square, part filled in yellow
    for k in range(len(arms)):
        color = colors[k % len(colors)]
        points = arms[k]
        label = None if labels is None else labels[k]
        ax.plot(points[:, 0], points[:, 1], color=color, linewidth=6,
                solid_capstyle='round', label=label, zorder=2)
        ax.scatter(points[:-1, 0], points[:-1, 1], s=50, color='white',
                   edgecolor=color, linewidth=2, zorder=3)
        ax.scatter(points[-1, 0], points[-1, 1], s=60, marker='s', color=color,
                   zorder=3)
        if parts is not None:
            corners = parts[k]
            ax.fill(corners[:, 0], corners[:, 1], facecolor='#FFEC7F',
                    edgecolor=color, linewidth=1.5, zorder=4)

    # target points as crosses
    if targets is not None:
        targets = np.atleast_2d(targets)
        ax.scatter(targets[:, 0], targets[:, 1], marker='x', s=80, color=gray,
                   linewidth=2, zorder=5, label='Target')

    if labels is not None or targets is not None or path is not None:
        ax.legend(loc='lower left')
    ax.set_xlim(-limit, limit)
    ax.set_ylim(-limit, limit)
    ax.set_aspect('equal')
    ax.grid(True)
    ax.set_xlabel('x in m')
    ax.set_ylabel('y in m')
    ax.set_title(title)
    plt.show()
import numpy as np
import matplotlib.pyplot as plt

# function from Chapter 5.1
def rotation_matrix(angle):
    """Rotation matrix for a rotation about the origin, angle in radians."""
    return np.array([
        [np.cos(angle), -np.sin(angle)],
        [np.sin(angle),  np.cos(angle)],
    ])

# swivel arm in the home position in m, row = [x, y]
arm = np.array([
    [0.0, 0.0],   # joint
    [0.6, 0.0],   # gripper
])

# corners of the lid under the gripper in m
lid = np.array([
    [0.55, -0.03],
    [0.65, -0.03],
    [0.65,  0.03],
    [0.55,  0.03],
])

# corners of the conveyor belt and the box (inside dimensions) in m
conveyor = np.array([[0.5, -0.8], [0.7, -0.8], [0.7, 0.8], [0.5, 0.8]])
box = np.array([[-0.54, 0.31], [-0.38, 0.31], [-0.38, 0.47], [-0.54, 0.47]])
box_center = np.array([-0.46, 0.39])

plot_robot(arm, parts=lid, targets=box_center,
           surroundings=[conveyor, box], title='Swivel arm in the home position')

The placement angle is therefore slightly more than 135°135°135°. The lid rotates along with the arm: at 90°90°90°, its long edge is parallel to the yyy-axis.

Part 2: Compute the placement angle

Instead of estimating, we try out all angles. Use np.linspace to create the angles from 0°0°0° to 180°180°180° in steps of 1°1°1°. In a loop, compute the gripper position for each angle and, with the Pythagorean theorem, its distance to the center of the box. Store the distances in an array distances that you create beforehand with np.zeros.

np.argmin works like np.argmax from Chapter 2.4 but returns the index of the smallest value. Use it to determine the placement angle. How far from the center of the box is the gripper at that angle? Plot the arm in the place position with the center of the box as the target.

# code cell
Solution Part 2
# swivel angles from 0 to 180 degrees in steps of 1 degree
angles_deg = np.linspace(0, 180, 181)
distances = np.zeros(len(angles_deg))

for k in range(len(angles_deg)):
    gripper = rotation_matrix(np.deg2rad(angles_deg[k])) @ arm[1]
    difference = gripper - box_center
    distances[k] = np.sqrt(difference[0]**2 + difference[1]**2)

# the index of the smallest distance gives the placement angle
k_best = np.argmin(distances)
place_angle = angles_deg[k_best]
print(f'Placement angle: {place_angle:.0f}°')
print(f'Remaining distance to the box center: {distances[k_best] * 1000:.1f} mm')

R_place = rotation_matrix(np.deg2rad(place_angle))
arm_place = (R_place @ arm.T).T
plot_robot(arm_place, targets=box_center, surroundings=[conveyor, box],
           title=f'Place position at {place_angle:.0f}°')

Output:

Placement angle: 140°
Remaining distance to the box center: 4.3 mm

At 140°140°140°, the gripper is at (−0.460,0.386)(-0.460, 0.386)(−0.460,0.386), 4.3 mm4.3\,\text{mm}4.3mm from the center of the box. This remaining distance has two different causes that we need to distinguish:

  • Error due to the grid: 140°140°140° is only the best angle on the 1°1°1° grid, not the exact best angle. A very fine grid gives 139.7°139.7°139.7°, where the remaining distance is 3.1 mm3.1\,\text{mm}3.1mm. The grid therefore costs a little over 1 mm1\,\text{mm}1mm, and with smaller steps this part can be made arbitrarily small. An error that arises only because we try a finite number of angles instead of all of them is called a discretization error.

  • Geometric mismatch: The center of the box is 0.603 m0.603\,\text{m}0.603m from the joint, but the gripper moves on a circle of radius 0.6 m0.6\,\text{m}0.6m. The gripper cannot reach the center of the box. Even at the exact best angle, 3.1 mm3.1\,\text{mm}3.1mm therefore remains, and no grid, however fine, changes that.

For the packaging line, a remaining distance of 4.3 mm4.3\,\text{mm}4.3mm is not critical, because the lid only has to fit into the box. We check this in Part 3.

Part 4: How long is the gripper’s path?

For the cycle time of the line, we need the length of the path that the gripper travels from the belt to the box. We approximate the circular arc with straight segments. To do this, write two functions:

  1. gripper_path(num_points) uses np.linspace to create evenly spaced angles from 0°0°0° to the placement angle and returns the gripper positions as an array of shape (num_points, 2).

  2. path_length(path) adds up the straight-line distances between consecutive points of the path, each computed with the Pythagorean theorem.

Compute the path length for 8, 29 and 141 points, i.e. for angle steps of 20°20°20°, 5°5°5° and 1°1°1°. Compare with the exact length of the circular arc L⋅αL \cdot \alphaL⋅α, where the angle α\alphaα must be in radians. Add the path with 8 points to the plot using the parameter path.

Why is the path made of straight segments always shorter than the circular arc?

# code cell
Solution Part 4
def gripper_path(num_points):
    """Gripper positions while swiveling from 0 degrees to the placement angle."""
    angles = np.linspace(0, place_angle, num_points)
    path = np.zeros((num_points, 2))
    for k in range(num_points):
        path[k] = rotation_matrix(np.deg2rad(angles[k])) @ arm[1]
    return path

def path_length(path):
    """Sum of the straight-line distances between consecutive points."""
    length = 0.0
    for k in range(len(path) - 1):
        difference = path[k + 1] - path[k]
        length += np.sqrt(difference[0]**2 + difference[1]**2)
    return length

# exact arc length: radius times angle in radians
arc_length = 0.6 * np.deg2rad(place_angle)
print(f'Exact circular arc: {arc_length:.5f} m')

for num in [8, 29, 141]:
    length = path_length(gripper_path(num))
    print(f'{num:3d} points: {length:.5f} m, error {(arc_length - length) * 1000:.2f} mm')

plot_robot([arm, arm_place], parts=[lid, lid_place],
           path=gripper_path(8), surroundings=[conveyor, box],
           labels=['Pick', 'Place'], title='Gripper path with 8 points')

Output:

Exact circular arc: 1.46608 m
  8 points: 1.45864 m, error 7.43 mm
 29 points: 1.46561 m, error 0.47 mm
141 points: 1.46606 m, error 0.02 mm

The gripper travels just under 1.47 m1.47\,\text{m}1.47m. Each straight segment is a chord of the circle and therefore shorter than the corresponding arc, so the sum is always slightly too small. With smaller angle steps, the approximation improves quickly: if the step size is divided by four, from 20°20°20° to 5°5°5°, the error drops from 7.43 mm7.43\,\text{mm}7.43mm to 0.47 mm0.47\,\text{mm}0.47mm, i.e. to about one sixteenth. The error decreases with the square of the step size. We will look at this order of the error more closely in later chapters on numerical differentiation and integration.

Closing question

  1. The center of the box is 0.603 m0.603\,\text{m}0.603m from the joint. What would happen if the box were closer to the base, for example with its center at (−0.30,0.30)(-0.30, 0.30)(−0.30,0.30)?

  2. The lid lies at an angle in the box. For stacking, its long edge should be parallel to the xxx-axis. Why is the swivel arm unable to do this, and what additional motion would it need?

Solution closing question

  1. The arm has only one joint. The gripper therefore always moves on a circle of radius 0.6 m0.6\,\text{m}0.6m around the joint, and its position is determined by the angle α\alphaα alone. A box center at (−0.30,0.30)(-0.30, 0.30)(−0.30,0.30) is only 0.424 m0.424\,\text{m}0.424m from the joint. The gripper would never get closer to it than 0.6 m−0.424 m=0.176 m0.6\,\text{m} - 0.424\,\text{m} = 0.176\,\text{m}0.6m−0.424m=0.176m and would miss the box. To reach points in a whole area, the arm needs a second joint at the end of the first arm, like the SCARA robot from Chapter 5.1.

  2. The orientation of the lid is rigidly coupled to the swivel angle: when the arm swivels by 140°140°140°, the lid also rotates by 140°140°140°. To place it straight, the lid would also have to be rotated about its own center; because of its symmetry, 40°40°40° is enough. Real packaging lines have a rotating gripper for this. Our rotation matrix, however, rotates only about the origin. A rotation about another point is made up of a rotation and translations. In Chapter 5.3 we will learn how to describe both in a single matrix.

Bonus exercise: Stop at the inspection camera (✩✩✩)

On its way to the box, the arm stops at 60°60°60°, where a camera inspects the lid. The swivel motion then consists of two rotations: first R1=R(60°)\mathbf{R}_1 = \mathbf{R}(60°)R1​=R(60°) from the belt to the camera, then R2=R(80°)\mathbf{R}_2 = \mathbf{R}(80°)R2​=R(80°) from the camera to the box. The rotation applied first therefore appears on the right.

At the camera, the gripper is at (0.300,0.520)(0.300, 0.520)(0.300,0.520). Two consecutive rotations combine into a single rotation by the sum of the angles, 60°+80°=140°60° + 80° = 140°60°+80°=140°. Both rotations are about the same point, the joint. Since the order of the terms does not matter in a sum, R1⋅R2=R2⋅R1\mathbf{R}_1 \cdot \mathbf{R}_2 = \mathbf{R}_2 \cdot \mathbf{R}_1R1​⋅R2​=R2​⋅R1​ as well. This is a special property of rotations about the same point in the plane. In general, matrix multiplication is not commutative. In Chapter 5.3, translations come into play, and then the order does matter.
