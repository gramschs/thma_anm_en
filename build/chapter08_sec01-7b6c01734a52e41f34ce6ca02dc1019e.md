# 8.1 Cost Function and Gradient Descent

A company assembles gearboxes and uses 12,000 ball bearings of the same type
per year. So far, the purchasing department has ordered 500 bearings every two
weeks. Each order costs €50 for processing, shipping and incoming inspection,
no matter how many bearings are delivered. Each bearing in stock costs €1.20
per year for storage space, insurance and the capital tied up in it. *Should
the company order less often and buy more at a time?*

A task in which we look for the best value of a quantity is called an
**optimization problem**. In Chapter 7.2 we computed the derivative of a
Python function with the central difference quotient. In this chapter, we use
the derivative as a signpost that points to the smallest value of a function.
The method is called **gradient descent**. It is built into many optimization
programs in design and manufacturing and is the most important tool for
training neural networks.

## Which order quantity is the cheapest?

The number of bearings the company orders at a time is called the **order
quantity** $Q$. The annual cost consists of two parts.

* With an annual demand of $D$ units, the company places $D / Q$ orders per
  year. Each order costs $C_O$, so together they add up to the **ordering
  costs** $D / Q \cdot C_O$.
* After each delivery, there are $Q$ bearings in stock. Until the next
  delivery, the stock decreases uniformly to zero, so on average $Q / 2$ units
  are in stock. With the holding cost rate $c_H$ per unit and year, this gives
  the **holding costs** $Q / 2 \cdot c_H$.

Together, they give the total cost per year:

$$C(Q) = \frac{D}{Q} \cdot C_O + \frac{Q}{2} \cdot c_H.$$

| Symbol | Meaning | Value | Name in code |
| --- | --- | --- | --- |
| $Q$ | order quantity | unknown, currently 500 units | `quantity` |
| $D$ | annual demand | 12,000 units | `demand` |
| $C_O$ | cost per order | €50 | `cost_per_order` |
| $c_H$ | holding cost rate | €1.20 per unit and year | `holding_rate` |
| $C(Q)$ | total cost per year | in € | `total_cost()` |

A capital $C$ stands for amounts of money in €, a lowercase $c$ for rates per
unit and year.

First, we define the known quantities. In the code, we use descriptive names
instead of the symbols. The last column of the table shows which name belongs
to which symbol.

```{code-cell} python
import numpy as np
import matplotlib.pyplot as plt

# annual demand D in units
demand = 12000
# cost C_O per order in €
cost_per_order = 50
# holding cost rate c_H in € per unit and year
holding_rate = 1.2
```

We write the total cost as a function of the order quantity.

```{code-cell} python
def total_cost(quantity):
    """Annual cost C(Q) in € for the order quantity Q = quantity."""
    ordering_cost = demand / quantity * cost_per_order
    holding_cost = quantity / 2 * holding_rate
    return ordering_cost + holding_cost
```

We compare the current order quantity of 500 units with half, double and four
times that quantity.

```{code-cell} python
# total cost for a few order quantities
for quantity in [250, 500, 1000, 2000]:
    cost = total_cost(quantity)
    print(f'Order quantity {quantity:4d} units: €{cost:7.2f} per year')
```

So far, the company pays €1,500 per year. With 1000 units per order, it would
pay only €1,200, but with 2000 units it would be back at €1,500. So the
minimum lies somewhere in between. *Where exactly?* To see this, we evaluate
the function for 400 order quantities between 100 and 4000 units.
`total_cost()` contains only basic arithmetic, and NumPy performs it
element-wise. So if we pass an array of order quantities, we get an array of
costs back.

```{code-cell} python
# 400 order quantities from 100 to 4000 units
quantity_values = np.linspace(100, 4000, 400)
cost_values = total_cost(quantity_values)
```

The plot shows the total cost against the order quantity. We highlight the
point of the current order quantity.

```{code-cell} python
# plot: total cost against order quantity
fig, ax = plt.subplots(figsize=(7, 4))
ax.plot(quantity_values, cost_values)
ax.plot(500, total_cost(500), marker='o', color='red', label='current')
ax.set_xlabel('Order quantity in units')
ax.set_ylabel('Total cost in € per year')
ax.set_title('Ordering and holding costs')
ax.set_ylim(0, 4000)
ax.legend()
ax.grid(True)
plt.show()
```

On the left, the curve drops steeply, and on the right, it rises slowly. In
between lies a flat valley with the minimum at about 1000 units and €1,200.
For small order quantities, the many orders drive up the cost, and for large
ones, the full warehouse does.

```{admonition} What is a cost function?
:class: note
In optimization, a function whose smallest value gives the best solution is
called a **cost function**. The point at which it takes its minimum is called
the **minimizer**. Here the cost function actually measures euros, but that
does not have to be the case. Any function we want to minimize is called a
cost function, for example the deviation between a model and measured data
(Chapter 8.2) or the transport effort in truck-kilometers per week
(Chapter 8.3). In machine learning, the cost function is called the **loss
function**. In business studies, the term has a narrower meaning: the cost as
a function of the production volume.
```

## Which way is downhill?

For the plot, we evaluated the function 400 times and still know the minimum
only approximately. If the cost depends on several quantities, the number of
evaluations grows very quickly. With two quantities and 400 values each, there
are already 160,000, and with three quantities, 64 million. So let us imagine
that we only know the value at the current order quantity and want to walk
downhill from there, like hiking in fog.

The slope, i.e. the derivative $C'(Q)$, tells us the direction. If it is
negative, the cost decreases as the order quantity increases, and we should
order more. If it is positive, we should order less. **Gradient descent**
turns this into a rule:

$$Q_\text{new} = Q - \alpha \cdot C'(Q).$$

The minus sign makes sure that we move against the slope, i.e. downhill. The
number $\alpha > 0$ is called the **learning rate**. It determines how far we
move relative to the slope. Where the curve is steep, we take large steps.
Close to the minimum, the slope is almost zero, and the steps automatically
become small. We call each pass through this calculation an **iteration**.
The name "gradient" comes from Chapter 8.3, where the cost depends on two
quantities. For a single quantity, the gradient is simply the derivative.

We compute the derivative with the central difference quotient from
Chapter 7.2. Instead of the time `t`, the variable is now called `point`,
because it can be any quantity. As announced in Chapter 7.2, we use the step
size $10^{-6}$.

```{code-cell} python
def central(function, point, dx):
    """Central difference quotient of function at the given point."""
    return (function(point + dx) - function(point - dx)) / (2 * dx)
```

At the current order quantity of 500 units, we get the following slope.

```{code-cell} python
# slope of the cost function at the current order quantity
slope = central(total_cost, 500, 1e-6)
print(f'Slope at 500 units: {slope:.4f} €/unit')
```

The slope is negative. If the company orders one more bearing at a time, the
annual cost drops by about €1.80. So we should move to the right. The rule of
thumb for the step size from Chapter 7.2 applies to quantities around 1. The
order quantity is around 1000, so the best step size would be larger.
However, the error with $10^{-6}$ is below $10^{-7}$ €/unit and does not
matter.

We take one step with the learning rate 200.

```{code-cell} python
# one step of gradient descent
learning_rate = 200
quantity = 500
quantity_new = quantity - learning_rate * slope

# cost before and after the step
cost_old = total_cost(quantity)
cost_new = total_cost(quantity_new)
print(f'New order quantity: {quantity_new:.1f} units')
print(f'Cost before: €{cost_old:.2f}, after: €{cost_new:.2f}')
```

A single step takes us from 500 to 860 units and lowers the cost from €1,500
to €1,213.67. The learning rate 200 seems large, but it is not. The product
$\alpha \cdot C'(Q)$ has to be a number of units, but the slope has the unit
€/unit. So how large a suitable learning rate is depends on the units of the
problem.

Now we repeat the step ten times in a loop. We append each new order quantity
to the list `history` with `append()`.

```{code-cell} python
# ten iterations of gradient descent, starting at 500 units
quantity = 500
history = [quantity]
for k in range(10):
    slope = central(total_cost, quantity, 1e-6)
    quantity = quantity - learning_rate * slope
    history.append(quantity)

print('Order quantities:', np.round(history, 1))
```

The order quantity grows from iteration to iteration, but more and more
slowly: first by 360 units, then by 42, and in the end by only 3. This is not
due to the learning rate, which stays at 200. The slope gets smaller the closer
we get to the minimum. After ten iterations, we are at 991 units, just short of
the minimum.

## When have we arrived?

So far, we have specified a fixed number of iterations. It is better to stop
as soon as we have reached the minimum. The slope is zero there. In the
calculation, however, it never becomes exactly zero, so we specify a small
**tolerance**. If the absolute value of the slope is smaller than the
tolerance, we stop. Such a condition is called a **stopping criterion**. The
slope has the unit €/unit, and we choose $10^{-4}$ €/unit as the tolerance.

`abs()` computes the absolute value. The statement `break` ends a `for` loop
immediately, even if it has not finished all its passes. We still limit the
number of passes with `max_iterations`. This way, the calculation also ends
if the stopping criterion is never met. We wrap the whole method in a
function.

```{code-cell} python
def gradient_descent(function, start, learning_rate, tolerance,
                     max_iterations):
    """Search for a minimum of function, starting at start.

    Returns all visited points as an array.
    """
    point = start
    history = [point]
    for k in range(max_iterations):
        slope = central(function, point, 1e-6)
        # stopping criterion: slope almost zero
        if abs(slope) < tolerance:
            break
        point = point - learning_rate * slope
        history.append(point)
    return np.array(history)
```

We start again at 500 units with the learning rate 200. The number of
iterations is one less than the length of the history, because the first entry
is the starting value.

```{code-cell} python
# gradient descent with stopping criterion
history = gradient_descent(total_cost, 500, 200, 1e-4, 100)

# result: number of iterations, order quantity and cost at the end
n_iterations = len(history) - 1
quantity_best = history[-1]
cost_best = total_cost(quantity_best)
print(f'{n_iterations} iterations')
print(f'Order quantity: {quantity_best:.2f} units')
print(f'Total cost: €{cost_best:.2f} per year')
```

After 28 iterations, the slope is smaller than the tolerance. The method finds
the order quantity 999.94 units, i.e. 1000 units after rounding, with a cost
of €1,200 per year. If the company orders 1000 bearings every month from now
on instead of 500 every two weeks, it saves €300 per year.

```{admonition} From business studies: the EOQ formula
:class: note
For this simple model, the minimizer can also be computed exactly. The
**economic order quantity (EOQ) formula** is
$Q^* = \sqrt{2 \cdot D \cdot C_O / c_H}$. With our numbers, it gives
$\sqrt{2 \cdot 12000 \cdot 50 / 1.2} = 1000$ units. As soon as the model
becomes more detailed, for example with quantity discounts or limited storage
space, such formulas usually no longer exist. Gradient descent, on the other
hand, only needs the cost function as a Python function.
```

*Which learning rate is the right one?* We compare four learning rates and
plot the order quantity against the iteration. Such a plot shows whether and
how quickly the method approaches the minimum. This behavior is called
**convergence**. `ax.axhline()` draws the horizontal line at 1000 units.

```{code-cell} python
# plot: order quantity against iteration for four learning rates
fig, ax = plt.subplots(figsize=(7, 4))
for learning_rate in [50, 200, 800, 2000]:
    history = gradient_descent(total_cost, 500, learning_rate, 1e-4, 100)
    ax.plot(history, marker='.', label=f'learning rate {learning_rate}')
ax.axhline(1000, color='gray', linestyle='--')
ax.set_xlim(0, 30)
ax.set_xlabel('Iteration')
ax.set_ylabel('Order quantity in units')
ax.set_title('Convergence of gradient descent')
ax.legend()
ax.grid(True)
plt.show()
```

The four learning rates show typical behavior.

* With the learning rate 50, the order quantity creeps toward the minimum.
  After 100 iterations, the stopping criterion is still not met.
* With the learning rate 200, it approaches the minimum steadily from below.
* With the learning rate 800, the first step jumps far past the minimum, to
  1940 units. Because the curve is flat on the right, it still comes back
  quickly and reaches the goal after only seven iterations.
* With the learning rate 2000, it jumps across the valley with every step and
  in the end oscillates endlessly between 815 and 1421 units. The method
  **does not converge**.

There is no learning rate that always works. If it is too small, the method
needs many iterations. If it is too large, the method starts jumping back and
forth. In practice, we try out a few learning rates and look at the
convergence plot.

## Summary and outlook

A cost function assigns to each value of a quantity a value that we want to
make as small as possible, here the annual cost of ordering and holding.
Gradient descent searches for its minimum without evaluating the function
everywhere. Starting from an initial value, it moves step by step against the
slope, following the rule $Q_\text{new} = Q - \alpha \cdot C'(Q)$. We compute
the slope with the central difference quotient from Chapter 7.2. The learning
rate $\alpha$ determines whether the method converges slowly, quickly or not
at all. A stopping criterion ends the calculation as soon as the slope is
almost zero.

In Chapter 8.2, you set up a cost function yourself that measures how well a
model fits measured data, and you use `gradient_descent()` to determine the
parameter for which the model and the measurements agree best. In
Chapter 8.3, the cost depends on two quantities at once: we look for the
location of a central warehouse. The derivative then becomes the gradient.
